REVYN – UI/UX FIX SPECIFICATION (v2 — Winner-Ready Pass)
==========================================================
Prepared for: revyn-web.vercel.app
Pages audited: Dashboard (/), Settings & Safety (/settings)
Goal: Fix cramped spacing, restore a real logo mark, unify color system,
stop button/text overflow, and properly space the search + filter bar.

---------------------------------------------------------------
0. WHAT CHANGED SINCE LAST PASS
---------------------------------------------------------------
- Root spacing scale wasn't applied consistently — Settings page is
  worse than Dashboard (rules, toggles, and integration cards all
  touching each other with no card separation).
- "Logo" issue: you currently only have a text wordmark "RevynAI" with
  no icon/mark. A text-only wordmark reads as unfinished for a judged
  demo — add an actual icon mark (spec below).
- Buttons ("Activate Kill Switch", "Run Batch Recovery", batch-size
  pills) have fixed/near-minimum widths — long labels are clipping or
  hugging the edges. Fix with proper padding + min-width + white-space
  rules below.
- Search/filter bar has zero gap between icon and input text.

---------------------------------------------------------------
1. GLOBAL SPACING SCALE (apply everywhere — this is the root cause
   of "cramped" across both pages)
---------------------------------------------------------------
Define these as CSS variables / Tailwind theme values and use ONLY
these — no arbitrary one-off px values anywhere in the app:

  --space-1:  4px
  --space-2:  8px
  --space-3:  12px
  --space-4:  16px
  --space-5:  20px
  --space-6:  24px
  --space-8:  32px
  --space-10: 40px
  --space-12: 48px
  --space-16: 64px

Rules of thumb going forward:
  - Space INSIDE a card (padding): --space-6 (24px) minimum, --space-8
    (32px) for the outer page container.
  - Space BETWEEN sibling cards/sections: --space-6 (24px) minimum.
  - Space between a label and its value (e.g. "Max Retry Limit" →
    "3 attempts"): --space-2 (8px).
  - Space between a heading and the paragraph under it: --space-2 (8px).
  - Space between a paragraph and the next control (button, toggle):
    --space-5 (20px) minimum — this is currently near 0 on Settings.

9. BUTTON SYSTEM (fixes text overflow across the whole site)
---------------------------------------------------------------
Apply to every button in the app, no exceptions:
  - min-width: 120px (default), 200px+ for primary CTAs with longer
    labels ("Run Batch Recovery", "Activate Kill Switch")
  - padding: 12px 24px (default size), 8px 16px (small/pill size)
  - white-space: nowrap (never let button text wrap or clip)
  - If a label risks exceeding its container on mobile, reduce
    font-size to 13px at <480px rather than truncating or wrapping
  - border-radius: 8px (all standard buttons), 999px (pill/segmented
    controls only)
  - Vertically center label with icon (if present) using flex,
    align-items: center, gap: 8px

---------------------------------------------------------------
11. WHY THIS ORGANIZATION FITS THE PROJECT
---------------------------------------------------------------
- Card-per-concern layout (esp. on Settings) mirrors the product's own
  architecture — Diagnose / Decide / Execute / Audit are separate,
  bounded steps, so the UI should visually separate them the same way,
  not present them as one dense paragraph.
- The 2x2 policy-rule grid and 3-column integration grid make the
  "bounded, deterministic" pitch scannable in 5 seconds — critical for
  a judge doing a quick pass.
- Distinct danger styling on the Kill Switch signals "we take this
  seriously" — matches the safety-first narrative in your project doc.
- A real logo mark (not just text) plus consistent spacing scale is
  the single fastest way to move this from "hackathon repo" to
  "presentable product" in judges' first-impression window.
