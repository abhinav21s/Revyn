REVYN – UI/UX FIX SPECIFICATION
=================================
Prepared for: revyn-web.vercel.app
Context: Bounded AI Payment Recovery Agent (Razorpay AI Buildathon, Track 3)
Goal: Elevate from "hackathon demo" to "fintech-grade product" look

---------------------------------------------------------------
1. COLOR SYSTEM (replace current ad-hoc dark theme)
---------------------------------------------------------------
Rationale: This is a fintech/compliance product. The palette needs to say
"trustworthy, audited, safe" — not generic AI-startup purple/gradient.
Keep the dark base (already on-brand via theme-color #0B0F19) but structure
it into a proper token system instead of flat black/gray.

BASE (background layers — creates depth without clutter):
  --bg-canvas:        #0B0F19   (page background, keep as-is)
  --bg-surface:        #121826   (cards, panels)
  --bg-surface-raised: #1A2233   (header bar, table header row, modals)
  --bg-surface-hover:  #202B40   (row hover, button hover)
  --border-subtle:     #26304566  (hairline borders, 40% opacity)
  --border-default:    #2E3A52

TEXT:
  --text-primary:   #F4F6FA
  --text-secondary: #94A3B8
  --text-muted:     #5B6B85

BRAND / ACCENT (primary action color — pick ONE, not blue+purple+green all at once):
  --accent-primary:      #4F7CFF   (electric indigo-blue — trust + tech)
  --accent-primary-hover:#6B91FF
  --accent-primary-dim:  #4F7CFF1A (10% opacity, for active-state backgrounds)

STATUS COLORS (used in "Root Cause" / "Status" columns — needs to be
immediately scannable since this is an audit-trail product):
  --status-recovered:    #22C55E  (green)
  --status-recovered-bg: #22C55E1A
  --status-in-progress:  #F59E0B  (amber)
  --status-in-progress-bg:#F59E0B1A
  --status-escalated:    #EF4444  (red)
  --status-escalated-bg: #EF44441A
  --status-unrecoverable:#64748B  (slate gray, deliberately desaturated —
                                   signals "closed/inactive", not alarming)
  --status-unrecoverable-bg:#64748B1A

GUARDRAIL / SAFETY BADGE (this is your key differentiator — give it its
own distinct color so judges' eyes go straight to it):
  --guardrail-active: #22C55E
  --guardrail-badge-bg: #0F2A1C
  --guardrail-badge-border: #22C55E4D

Do NOT use more than 2 accent hues total (accent-primary + status colors
count as functional, not decorative). Avoid rainbow gradients on buttons.

2. HEADER (currently cramped)
---------------------------------------------------------------
Problems observed: logo, tagline, badges ("Policy Engine Active",
"Guardrails enforced", "v1.0.0") and nav links are all fighting for the
same horizontal row with no breathing room.

Fix — restructure into 2 rows:

ROW 1 (Height: 64px, background: --bg-surface-raised, border-bottom: 1px
solid --border-subtle):
  - Logo "RevynAI"        → left-aligned, padding-left: 32px
  - Logo font-size: 20px, font-weight: 700, letter-spacing: -0.02em
  - Nav links (Dashboard / Recoveries / Audit Trail / Settings & Safety)
    → horizontally centered as a group, gap: 32px between each link
    → font-size: 14px, font-weight: 500, color: --text-secondary
    → active link: color: --text-primary, with a 2px --accent-primary
      underline, 8px below text
  - Right side: "Razorpay Test Mode Only" badge
    → padding: 6px 12px, border-radius: 6px, background: --status-in-progress-bg,
      border: 1px solid --status-in-progress4D, font-size: 12px
    → padding-right: 32px from edge

ROW 2 (Height: 44px, background: --bg-canvas, border-bottom: 1px solid
--border-subtle):
  - "Revenue Recovery Agent" tagline → left, padding-left: 32px,
    font-size: 13px, color: --text-muted
  - "Policy Engine Active" + "Guardrails enforced · v1.0.0" → move here,
    right-aligned, padding-right: 32px, gap: 16px between the two badges
  - Each badge: padding 4px 10px, border-radius: 999px (pill shape),
    font-size: 11px, with a 6px green dot (●) before "Policy Engine Active"

Overall: header total height goes from whatever cramped single row it is
now to 108px (64+44), giving each element its own lane instead of
overlapping visually.

3. PAGE LAYOUT / LEFT SECTION (currently too cramped)
---------------------------------------------------------------
Current issue: "Execute Recovery Pipeline" panel and page content sit too
close to the viewport edge and to each other, no clear grid.

Fix:
  - Page container: max-width: 1280px, centered (margin: 0 auto)
  - Page horizontal padding: 32px (desktop), 16px (mobile <768px)
  - Top padding below header: 40px before "Revenue Recovery Overview" H1
  - Section vertical gap: 24px between every major block (H1 block →
    Execute Recovery Pipeline card → Recent Payment Cases card)

"Execute Recovery Pipeline" card:
  - padding: 24px all sides (currently reads like 8-12px)
  - border-radius: 12px
  - background: --bg-surface
  - border: 1px solid --border-subtle
  - Title "Execute Recovery Pipeline": font-size 16px, font-weight 600,
    margin-bottom: 8px
  - Description text below title: font-size 14px, color --text-secondary,
    line-height: 1.5, margin-bottom: 20px, max-width: 640px (don't let
    it stretch full width, hurts readability)
  - Batch size selector (10/20/50 cases): convert from plain text list to
    3 segmented pill buttons, each padding: 8px 16px, gap: 8px between
    pills, selected pill: background --accent-primary, text white;
    unselected: background --bg-surface-raised, text --text-secondary
  - "Run Batch Recovery" button: padding: 12px 24px, border-radius: 8px,
    background --accent-primary, font-weight: 600, font-size: 14px,
    margin-top: 20px, full-width on mobile only

If this "Execute Recovery Pipeline" block is meant to sit in a LEFT
SIDEBAR alongside a right-hand results panel (recommended for this
dashboard type):
  - Left column width: 320px fixed
  - Right column: flex: 1 (remaining space)
  - Gap between columns: 24px
  - Left column becomes sticky (position: sticky, top: 88px) so it
    stays visible while the case table scrolls

4. SEARCH BAR / FILTER TABS (currently unstyled)
---------------------------------------------------------------
Observed: "All / Recovered / In Progress / Escalated / Unrecoverable"
with counts (0) appear as plain unstyled text tabs.

Fix — convert to a proper filter bar:
  - Container: display flex, gap: 8px, padding: 16px 0, border-bottom:
    1px solid --border-subtle, margin-bottom: 16px
  - Each tab: padding: 8px 16px, border-radius: 8px, font-size: 13px,
    font-weight: 500
    - Inactive tab: background transparent, color --text-secondary,
      border: 1px solid transparent
    - Active tab (e.g. "All"): background --accent-primary-dim,
      color --accent-primary, border: 1px solid --accent-primary4D
    - Count badge inside tab (the "0"): separate pill, margin-left: 6px,
      padding: 1px 6px, border-radius: 999px, background --bg-surface-raised,
      font-size: 11px
  - Color-code the non-"All" tabs using their matching status color at
    20% background when active (Recovered → green tint, Escalated →
    red tint, etc.) so the filter bar itself previews the color coding
    used in the table below.

If there's meant to be an actual search input (searching by case/customer):
  - Height: 40px, width: 320px (desktop), 100% (mobile)
  - padding: 0 16px 0 40px (left padding accounts for icon)
  - border-radius: 8px, border: 1px solid --border-default,
    background: --bg-surface
  - Search icon: 16px, positioned absolute, left: 12px, top: 12px,
    color --text-muted
  - Focus state: border-color --accent-primary, box-shadow:
    0 0 0 3px --accent-primary-dim
  - Placeholder text color: --text-muted
  - Position: same row as filter tabs, right-aligned, or its own row
    with 12px margin-bottom above the filter tabs

---------------------------------------------------------------
7. WHY THESE CHOICES FIT THE PROJECT
---------------------------------------------------------------
- Dark, structured, low-saturation base = "compliance/audit tool," not
  "flashy AI toy" — matches the project's core pitch of a bounded,
  deterministic Policy Engine that judges should trust.
- Status color-coding (green/amber/red/gray) mirrors the five case states
  in your own workflow (Recovered / In Progress / Escalated /
  Unrecoverable) so the UI visually reinforces the audit-trail concept.
- A single accent blue (not a gradient or multiple brand colors) keeps
  focus on data, since the product's differentiator is measurable
  recovered revenue, not visual flair.
- The guardrail badge gets its own treatment because "Guardrails
  enforced" is your single strongest judging-criteria hook — it should
  visually stand out from generic nav/status elements.
